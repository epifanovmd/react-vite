# ADR-0002: защита документов текстовым правилом

- Статус: принято; заменяет защиту хуком из ADR-0001
- Дата: 2026-11-02

## Контекст

ADR-0001 ввёл хук `PreToolUse`, который отклонял запись в защищённые документы до
разблокировки командой пользователя. Для shell-команд хук разбирал текст команды
эвристикой и давал ложные срабатывания: на относительных путях, разрешённых не от того
каталога, на именах веток вида `docs/…`, на строках с путями внутри скриптов и
сообщений коммитов. Это мешало работе и не повышало
надёжность — защита от осознанного обхода хуком не обеспечивается в принципе.

## Решение

- Хуки `protect-docs`, `docs-unlock` и их регистрация удалены, skill `/docs-lock` —
  тоже.
- Правило — текстом: правила и документы меняются только по явному указанию
  пользователя ([meta/protection](../../00-meta/protection.md)); `/docs-edit` остаётся
  удобной формой такого указания.
- Новые правила по-прежнему предлагаются через `docs/inbox/`.

## Последствия

- Нет ложных блокировок; соблюдение правила — ответственность агента, проверяется на
  ревью.
- Общий слой системы знаний одинаков в проектах и не требует проектных хуков.
