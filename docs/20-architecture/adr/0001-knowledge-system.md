# ADR-0001: система знаний проекта

- Статус: принято; скрипты системы знаний (индекс, проверки документов, формат коммитов) отменены — правила соблюдаются по тексту, индексы ведутся вручную; защита хуком заменена ADR-0002
- Дата: 2026-11-02

## Контекст

Правила жили в шести больших корневых документах и в отдельной проектной памяти
агента. Между ними не было приоритетов и связей, нужное правило приходилось искать
чтением сотен строк, правила области не подгружались автоматически, этапы и запреты
держались только на тексте, документации модулей не было.

## Решение

- Уровни L0–L5 ([meta/doc-system](../../00-meta/doc-system.md)): `CLAUDE.md` →
  `.claude/rules` с `paths` → `docs/` и README модулей → skills → субагенты →
  автоматика.
- Мелкие документы с frontmatter (`id`, `layer`, `roles`, `stages`, `depends_on`),
  сгенерированный индекс, проверка `yarn docs:check` в `verify`.
- Документация модуля — `README.md` рядом с кодом; проектная конкретика из памяти
  агента перенесена туда и в `docs/50–70`, память упразднена.
- Защита правил хуком с разблокировкой командой пользователя `/docs-edit`; новые
  правила — через `docs/inbox/`.
- Коммиты — Conventional Commits на русском с проверкой хуком `commit-msg`.

## Альтернативы

- `@import` документов в `CLAUDE.md` — загружает всё сразу, токены не экономит.
- `CLAUDE.md` в каждом модуле — подгружается автоматически, но неудобен людям и
  другим инструментам; вместо этого правило L1 направляет к README.
- Только текстовые запреты — не защищают от случайной правки.

## Последствия

- Агент тратит меньше контекста: постоянно загружены только `CLAUDE.md`, описания
  skills и сработавшие правила.
- Правка правил требует явной команды; рост правил идёт через inbox.
- Новые модули обязаны иметь README — это проверяет `docs:check`.
