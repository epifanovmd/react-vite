# Защита правил и предложение новых

## Что защищено

Без явной команды пользователя не изменяются:

- `CLAUDE.md`, корневой `README.md`;
- `docs/**`, кроме `docs/inbox/`;
- `.claude/settings.json`, `.claude/hooks/`, `.claude/rules/`, `.claude/skills/`,
  `.claude/agents/`;
- машинные правила: `scripts/docs/`, `scripts/git/`, `lefthook.yml`, `eslint*.mjs`.

Не защищены и обновляются по ходу задачи:

- README модулей `src/**/README.md` — меняются вместе с кодом модуля;
- `docs/inbox/` — сюда агент пишет предложения.

## Механизм

Защиту обеспечивает хук `PreToolUse` (`.claude/hooks/protect-docs.mjs`): запись
в защищённый путь через Edit/Write или изменяющую shell-команду отклоняется.

Явная команда — сообщение пользователя, начинающееся с `/docs-edit`. Хук
`UserPromptSubmit` открывает правку на 60 минут текущей сессии; `/docs-lock` или новая
сессия закрывают её раньше. Агент сам разблокировать правку не может: файл-флаг
защищён тем же хуком.

Разблокировка разрешает правку только того, о чём попросил пользователь. Попутные
правки других документов — снова через предложение.

Хук — защита от случайности, а не от злого умысла: обходить её запрещено.

## Предложение правил

Агент предлагает запись, когда:

- ситуация может повториться, а правила для неё нет;
- правило противоречит другому или устарело относительно кода;
- задача изменила архитектурный факт, описанный в защищённом документе;
- пользователь дал указание, похожее на общее правило («всегда…», «никогда…»).

Порядок:

1. Создать файл `docs/inbox/<YYYY-MM-DD>-<slug>.md` по
   [шаблону](templates/inbox.md): что произошло, предлагаемый текст, целевой файл.
2. В итоговом сообщении задачи перечислить новые предложения.
3. После решения пользователя: принято — правка через `/docs-edit`, файл предложения
   удаляется; отклонено — файл удаляется.

Текущую задачу предложение не блокирует, если пользователь не сказал иначе.
