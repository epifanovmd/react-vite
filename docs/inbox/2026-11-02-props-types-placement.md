# Где объявлять тип пропсов компонента

## Ситуация

При описании модулей найдено три стиля: тип пропсов в отдельном
`<component>.types.ts` (`pages/profile`, `features/edit-profile`,
`features/sign-in` — PasskeyLogin, TwoFactorPrompt), интерфейс в файле компонента
(`SignInForm`, `SignUpForm`, `FileUploader`, `SessionRow` и др.) и инлайн-тип
(`UploadStatus`). Правило `naming` говорит только «типы одного крупного компонента —
`<name>.types.ts`», без критерия «крупного», поэтому выбор каждый раз делается заново.

## Предложение

Дополнить `docs/30-conventions/components.md`, раздел «Props»:

> Интерфейс пропсов объявляется в файле компонента, над компонентом, и
> экспортируется, если нужен снаружи. Отдельный `<component>.types.ts` — когда
> типов несколько (пропсы, варианты, колбэки) или их импортируют другие файлы
> модуля. Инлайн-тип в сигнатуре не используется.

## Обоснование

Ситуация повторяется в каждом новом компоненте; явный критерий убирает разнобой и
вопросы на ревью. Существующий код приводится к правилу только при правке файла.
