## Права

- Права — строки (`KnownPermission` в спецификации больше нет). Тип `Permission`, `ALL_PERMISSIONS` (`*`) — `@shared/lib/access` (реэкспорт из `@entities/user`); `ADMIN_PERMISSIONS` (user:view/update/delete/privileges, role:view/create/update/delete, profile:view/update/delete, apikey:view/create/revoke, audit:view) — `entities/user/lib/permissions.ts`; `JOB_PERMISSIONS.DEMO` (`jobs:demo`, только демо-задача `demoEchoJob`) — `entities/job/lib/permissions.ts`; `AGENT_PERMISSIONS` (`agent:view/manage/config/fetch/logs/enroll`) — `entities/agent/lib/permissions.ts`. `*:manage` больше нет — каждая кнопка по своему праву.
- Подписи и группы прав — только каталог сервера `GET /api/v1/permissions` (`getPermissionCatalog`, `{ groups: [{ key, label, permissions: [{ name, label }] }] }`, первая группа `*` «Система»). `entities/permission`: `IPermissionCatalogStore` (singleton, грузится один раз, после ошибки — повторно; `labelOf(name)`), `PermissionMatrix` (`value`/`onChange`, `readOnly`, `isLocked(name)`; уровни «Нет / Свои / Все» — см. `project_access.md`). В карточке роли `*` заблокирована, если текущий пользователь не суперпользователь (`isAdmin || can("*")`).
- `PermissionGate` (`@entities/user`, `permission` — право или список, любое): нет права (сразу или отозвано на открытой странице) → заглушка + `toast.warning` + `navigate({ to: "/", replace: true })`; ошибка `/me` → `Empty` с ошибкой вместо вечного лоадера. Пункты навигации — `NavItem.permission` (право или список, any-of), фильтр в `useHeaderVM`.
- VM страницы грузит данные и входит в комнату только с правом просмотра (`enabled: canView`, `useSocketRoom(type, canView ? "all" : null)`); флаги действий `canCreate/canUpdate/canDelete/canRevoke/canEditPrivileges` отдаёт VM.
- Модалки закрываются при отзыве права — `useCloseWhenForbidden(open, allowed, close)` из `@shared/lib/hooks` (сейчас — модалка прав пользователя в `useAdminUsersVM`).
- Модалка прав пользователя без `role:view` не грузит роли: показывает назначенные, чекбоксы ролей disabled.

## Реакция на смену прав и сессий

- `AUTH_PRIVILEGES_CHANGED` (401) — старый access после смены прав; `bearerAuth` на любой 401 обновляет токен и повторяет запрос, сессия остаётся. Сокет `user:privileges-changed {roles, permissions}` → `UserRealtime` делает `userStore.refresh()`.
- `session:terminated` с `sessionId: "all"` (аккаунт удалён) или текущей сессией → `signOut()` (`SessionStore.handleSessionTerminated`).
- Выход (`AppDataStore`, `isAuthenticated → false`): `userStore.reset()` (+ privacy), `sessionStore.reset()`, `jobStore.reset()` — следующий вход в той же вкладке не видит прежних прав.
- Ошибки сервера ROLE_SYSTEM_ROLE (409), ROLE_OWN_ROLE, USER_SUPERUSER_EDIT, PROFILE_SUPERUSER_EDIT — отдельной обработки нет, текст показывает `notifyApiError`.

## Навигация

- Группа без label — пункты в ряд; группа с label и >1 пунктом — выпадающее меню (`HeaderNavGroup`); `mobileOnly` — только в мобильном меню («Аккаунт», в шапке эти пункты в меню профиля через `ACCOUNT_NAV_ITEMS`).

## Gotcha

- Аудит отдаёт курсор `{items, nextCursor}` — `AuditFeed` (CursorHolder + свой `nextCursor`), не offset-холдеры.
- Пагинированные ответы `{items, total}` → для `usePaged` мапить в `{data, totalCount}`; для `CollectionHolder.fromApi` передавать extractor (`page => page.items`) — cast в fromApi скрывает ошибку от tsc.
- `Table` по умолчанию `flex-1` и растягивается на всю страницу — на обычных страницах `className="flex-none"`; пустое состояние — `labels={{ empty }}`, не строка в `empty`; тулбар лучше рендерить над таблицей (слот `toolbar` имеет свой `px-3`).
- Хуки холдеров без `watch` сами не грузят — `load()` в `useEffect`.
- 2FA-статуса в UserDto нет — экран даёт оба действия.
- Vite dev-сервер иногда не подхватывает новый routeTree.gen.ts — перезапуск.

## Агенты (протокол агента 1.0.0, с 13.10.2026)

- `AgentDto`: `online`, `revoked`, `version`, `updateMode`, `install`, `host {os, arch, hostname, kernel}`, `remoteIp`, время в мс (`enrolledAt`, `lastSeenAt`, `startedAt`), `updateAvailable` (агент сам нашёл версию), `desiredRev`/`appliedRev`, `outbox`, `workers[]` (IAgentWorkerDto: `state` starting|running|invalid|backoff|stopped|unknown, `message`, `health {ok, busy, message}` — пульс, `pending` restart|update, `release`, `restarts`, `updateAvailable` (сборка с сервера новее), `manifest {description, configs[{key, description, schema}], commands[{type, description, schema, result}], events[{type, schema}], requests[{type, schema, response}]}`), `metrics` (`{at, host, workers}`), `alerts[] {kind, worker?, key?, message}`. Встроенного воркера (`builtin`), маршрутов, `jobs`, `session/statusAt/connectedAt` нет.
- `entities/agent`: `IAgentsStore` — список (`getAgents` до 100), `release` (`getAgentRelease` → `{bundle, workers[]}`), `alerts`/`candidates` вычисляются из агентов (`IAgentAlert` = alert + agentId/agentName; `IAgentUpdateCandidate {agentId, worker?, current, target}`), `trackCommand/settleCommand/pendingCommand` — ждущие команды пользователя. `waitAgentCommand(api, command, signal)` — длинный опрос `getAgentCommand(…, {waitSeconds: 25}, {timeout: 35 с})` до `status: done`, сбой — повтор через 2 с. `useAgentReleaseWatch(enabled, {onUpdateAvailable})` — грузит список и сборки, сидит в комнате `agents`, сообщает о новых кандидатах за сессию (шапка: тост и значок у «Агенты»).
- Действия (`features/manage-agent`): всё — команды агенту. `useAgentCommand().run(key, request, onQueued)`: поставить → `trackCommand` → `waitAgentCommand` → `settleCommand` + `store.fetch`. Смена ключа и обновление агента (`updateAgent(id, {version?})`) — тост по итогу; воркер: `restart/update(…, force)`, занятому — тост «занят — агент заменит его, когда освободится» сразу, итог потом. `pendingOf(agent, worker)` — `worker.pending` или ждущая команда в сторе; `replaceNow` — update/restart с force.
- Удаление агента («Удалить», `deleteAgent`, любой агент с правом управления): запись и история удаляются, агент на узле получает 403 — переходит в `revoked`, останавливает воркеры с уборкой и больше не выходит на связь (программа остаётся до `agent uninstall`). «Отозвать» — то же на узле, но запись остаётся. Удаление узла = удаление агента. Новая установка с токеном возвращает агента (pending → active).
- `widgets/agent-tabs` — вкладки `overview | workers | configs | commands | events | logs`; `IAgentTabsAccess { canManage, canConfig, canCommand, canLogs }` (страница агента — `agent:command`, узел — `node:agent`). «Команды» без права скрыты.
  - Обзор: `AgentHostCard` — ядро, время работы узла, запуск агента, последняя связь, регистрация, применено желаемое (`appliedRev/desiredRev`), очередь на узле (`outbox`), метки.
  - Воркеры: `IWorkerRow {worker, metrics, pending}`; `updateTo` — `worker.updateAvailable` (только `release`); раскрытая строка — каталог: команды («аргументы · итог»), события, запросы к серверу, ключи настроек; сообщение пульса.
  - Настройки: `AgentConfigDto` плоский (`version, state pending|applied|failed, error, data?, updatedAt`; `data` — только с правом). `agent:config` без `data` — значение остаётся прежним, при другой версии/новом ключе — перечитать; `deleted` — убрать. PUT тело — само значение.
  - Команды: `features/send-worker-command` — `useWorkerCommandVM`: воркер (по умолчанию первый с командами), команда из `manifest.commands`, аргументы — «Форма» (`schemaFormFields`) или «JSON», срок (`timeoutMs`), отправка `sendAgentWorkerCommand(…, {waitSeconds: 0})`; история последних 20: `agent:command` + `waitAgentCommand`; «Отменить» → `cancelAgentCommand`. `AGENT_COMMAND_INVALID` — у поля с `details.reason`.
  - События: типы из манифестов + `command.progress` у воркера с командами.

## Gotcha (агенты)

- `queryRace` в HTTP-клиенте: новый запрос гасит незавершённый с тем же методом и путём (query не в ключе). Живому окну метрик передаётся `{ queryRace: false }`, иначе его гасит история.
- Связь «нет связи · N с назад»: `useTimeSince(at)` (`@shared/lib/hooks`, тик раз в секунду первую минуту, потом 15 с / 1 мин; формат `formatSince` из `@shared/lib/utils`) — в `AgentStatusBadge` (подпись «нет связи») и `NodeStatusBadge` («Нет связи», `node.agent.lastSeenAt`); в шапке узла и колонке «Агент» узлов «был …» убрано (дубль), в колонке «Связь» агентов — абсолютное время. Колонки статуса — 190.
- Мгновенность связи: `agent:updated` (offline через ~3 с) приходит в комнаты `agents`/`agent_<id>`; узлы — `node:updated` в `nodes`/`node_<id>` и лично владельцу/создателю (сигнатура агента включает `online` и воркеры) → списки агентов, узлов, главная, карточки обновляются сразу. Опроса в `useNodesVM` нет: `node:load` приходит в комнату `nodes` и лично своим; нагрузка показывается, только если `node.agent.online` (связь — из события узла, не из устаревшего агента).
- `AGENT_CONFIG_INVALID` (400): подробность — `details.reason` (`getErrorBody`), показывается у поля редактора, без тоста.
- `SchemaHint`/`SchemaHintField` — в `entities/agent/ui` (пропсы `label`, `emptyText`), общие для настроек, команд, событий, каталога. `schema-form.ts` (`schemaFormFields/Defaults/Body`), `errors.ts` (`agentErrorText`: COMMAND_UNDECLARED/INVALID, CONFIG_INVALID, EVENT_UNDECLARED, UNKNOWN_COMMAND, TIMEOUT, EXPIRED; с `AGENT_` и без) — `entities/agent/lib`. Задачи: `jobErrorText` — NO_AGENT, COMMAND_UNDECLARED/INVALID, TIMEOUT понятным текстом; `run-demo-job` — у `echo.quick` переключатель «Префикс от сервера» (`lookup`, запрос воркера `echo.lookup`).
- Методы MobX-стора нельзя `vi.spyOn` (non-configurable) — в тестах подставлять данные через API-мок.

## Узлы (с 08.10.2026)

- Права `NODE_PERMISSIONS` (`entities/node/lib/permissions.ts`): view/update/delete/assign/provision/agent/logs с областью `:own` (владелец или создатель — `nodeOwners`), `node:create` без области. Действия по строке — `canOn`.
- Комната `nodes` — только с `node:view` на все; свои узлы сервер шлёт лично (`node:updated/deleted/load`) — события слушаются при любой области.
- Карточка узла: комнаты `node` и `agent`; события агента фильтруются по `agentId` (комнаты `agents` у владельца узла нет). Сборки (`getAgentRelease`) — только с `agent:view`; новая версия — `node.agent.updateAvailable` / `agent.updateAvailable`.
- `widgets/agent-tabs` — общие вкладки агента для `agent-detail` и `node-detail`; права приходят пропом. На странице агента — `agent:manage/config/command/logs`, на узле — `node:agent` (управление, настройки, команды) и `node:logs`.
- `NodeDto.agent.workers[]` — кратко `{name, state, version, healthy, busy}`; `node.config.pending/failed` — ключи `воркер/ключ`.
- Навигация: «Узлы» (`node:view:own`) — основной пункт; «Агенты» (`agent:view`) — в группе «Администрирование» (все агенты, в т. ч. без узла, токены регистрации).
- На «Обзоре» агента нет карточки «Работает» (время работы); на карточке узла адрес/версия/связь — только в шапке.
